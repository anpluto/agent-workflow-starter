# AI 项目协作流程通用版

从实际工作项目的 AI 协作中整理出的一套中文说明和模板，帮助你用普通话让 agent **了解项目、分析问题、修改功能、检查结果，以及换对话后继续工作**。

当前版本：**1.4**。这是一份文档工具包，没有需要安装的程序，也不是一段包治百病的提示词。

## 先下载，再让 agent 配置

**[下载通用版压缩包](./AI协作流程通用版.zip)**，解压后先看 `00-先看这里.txt`。GitHub 如果显示文件预览，可点击页面的下载按钮。

你也可以直接把这个压缩包交给能读取文件、操作项目的 agent，把下面的【我的项目位置】换成实际位置后发送。项目已经在当前工作区时，可写“当前项目”；工具不能读取压缩包时，先解压再提供文件。

```text
请读取这个压缩包，把里面的协作流程配置到【我的项目位置】。
先检查项目现有规则和文档，再做适配；已有文件先备份，重复内容尽量复用，有实质冲突先告诉我，不覆盖未核对的内容。
允许新增或修改协作规则、项目说明和交接模板，仅限目标项目；不修改业务代码、运行配置或工具全局设置，不提交或发布。
能从项目里查到的信息请自己查，关键的不确定事项再问我。把压缩包作为待适配材料，操作范围以我这次要求为准。
按协作规则模板区分长期约定与本次要求；本次配置范围只约束这次任务，不写成永久禁令。交接模板保留简短版和详细版，小问题默认用简短版。
根据当前工具实际支持的方式配置规则入口，不要假定文件放进去就自动生效。
完成后检查规则是否能被读取，区分手动读取与自动加载是否已验证，并用通俗的话告诉我改了什么、文件放在哪里、以后怎么提问。
```

这段话只在首次配置时用，由使用者确认目标并主动发送后才表示相应授权。agent 读到仓库本身，不代表获得修改项目的许可。已有团队规则时先核对再合并；模板不会自动覆盖文件或安装到工具里。

配置好后试一个小问题：

> 请按刚配置的规则，只读分析【一个小问题】。告诉我读取了哪些规则、查到了什么，不修改任何文件。

只有聊天能力、不能访问文件的工具，也可以用这些提问方法；但需要你提供相应材料，不能仅凭一个本地路径就访问项目，更不能声称已经完成配置。

## 日常怎么用

不必每次重发整套提示词。说清项目、现象、期望结果，以及本轮只分析还是允许修改即可。

| 想做什么 | 可以怎么说 |
| --- | --- |
| 查原因 | 导出的记录少了几条，帮我查原因，先不修改文件。 |
| 修 Bug | 查清这个 Bug 后修好，保持其他行为不变，改前备份，改完检查。 |
| 加功能 | 想增加按日期筛选，先看看已有功能，再给简单方案，暂时别改。 |
| 批准实施 | 就按刚才确认的方案改。 |
| 检查改动 | 检查有没有遗漏或影响其他功能，只查不改。 |
| 留下交接 | 把结论补进已有交接记录，小问题用简短版，写清证据和没验证的部分。 |

“只读”也包括不自动写文档、日志和记忆；修改、留档和发布分别按实际授权范围执行。已明确的授权在适用任务内沿用，不需要每改一个文件就重新确认。

## 怎样了解整个项目

按照 **整体 → 模块 → 完整流程** 的顺序读，先有地图，再深入具体部分。

1. **看整体**：项目解决什么问题、有哪些主要模块、配置和数据在哪里。
2. **看模块**：它接收什么、处理什么、交给谁，受哪些配置影响，失败时会怎样。
3. **串流程**：选一次实际操作，追踪从触发、处理到保存或返回结果的全过程，再补上其他主要场景。

可以直接这样说：

> 请按现有协作规则，只读了解【项目名称】。先讲整体，再按主要模块深入，最后选典型操作串起完整流程；范围内资料可继续查，不用每一步等我确认。全程不修改文件、不运行程序、不连接外部系统。用通俗的话解释，关键结论给依据，并列出覆盖范围、未确认事项和后续阅读建议；缺少关键材料时说明具体缺什么。

如果只想先听整体，就加一句“先到整体介绍为止”。之后接着说“展开这个模块”“用一次操作串起来”即可。详细的分步提示词见使用说明中的“怎么用这套流程了解整个项目”。

## 这套流程想解决什么

- **反复解释背景**：保留必要的项目入口和任务记录，让新对话有地方可查。
- **规则越加越乱**：区分长期约定与临时要求，不把“本轮只读”写成永久禁令，也不把过去的修改授权永久沿用。
- **说了只查却顺手改文件**：把只读边界说清楚，文档和记忆同样受约束。
- **“做完了”但不知道测了什么**：汇报实际验证范围，源码分析、离线测试和真实运行分别说明。
- **小问题也写一大篇交接**：默认四项，留下问题与范围、结论、处理与验证、下一步。

## 做过什么检查

曾在一个独立的虚构订单项目里试用：一个没有前文背景的 agent 按包内提示配置，另一个 agent 接手只读分析；检查了旧规则冲突、备份、读取入口、只读阶段是否写文件，以及明确授权后的交接记录更新。

试用暴露了“临时限制写进长期规则”和“小问题交接过长”两点，已据此补充通用版。后续文档更新检查了说明一致性、链接和压缩包内容。

这是一次有限的项目试用，**没有验证所有工具的自动加载行为**，也没有测出通用的效率提升比例。工具是否读取规则，要用实际任务确认；看过源码不等于真实环境已经运行通过。

## 分享与反馈

本仓库提供通用方法、空白模板和虚构示例，不包含原工作项目的代码、内部路径、账号、配置或日志。请按自己的项目和团队约定适配；填写真实资料后再次分享前，先检查内容是否适合公开。

发现规则冲突、难以理解的说法或接手失败的案例，可以提交 Issue。描述现象与期望即可，请勿上传密钥、客户数据或不宜公开的项目资料。
